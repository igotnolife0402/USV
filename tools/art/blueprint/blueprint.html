C · RULES
  1. One entry point, run in one command written in README.
  2. SPEC before code: scope = exactly what was asked.
  3. No placeholders: real copy, real assets, max quality.
  4. Binaries out of git; the script that makes them in.
  5. One fact, one place; link everywhere else.
  6. Outputs to one fixed path every tool and agent reads.
  7. Done = outside check passed (tests/check.mjs, screenshot); never self-judged.
  8. Secrets only in .env (gitignored).
  9. Forward slashes, kebab-case names.
  10. Notes ≤150 lines; split by topic.
  11. Log + 1 improvement every session.
