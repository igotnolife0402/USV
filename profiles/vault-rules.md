# Vault rules (applied lessons)
- WebSearch/WebFetch can fail; fall back to curl on docs (code.claude.com/docs/en/<page>.md) and the GitHub API (api.github.com) (L-002)
- Cloud (phone) sessions load only the repo .claude/; plugins and ~/.claude skills/hooks never load there, so anything mobile needs must live in the repo (L-003)
- Hook additionalContext is cut at 10,000 chars; keep SessionStart injection <= 8000 chars total (L-004)
- MEMORY.md/auto-memory loads only the first 200 lines / 25KB; put critical facts at the top or in the vault (L-006)
- CLAUDE.md @imports load in full at start (no context savings); link notes instead of importing (L-007)
- On Windows hooks run in Git Bash; use forward slashes and quote "$CLAUDE_PROJECT_DIR" (path has a space) (L-008)
- Agent teams cost ~7x tokens; never use them for simple/medium tasks, huge tier only (L-015)
- Mobile never says "failed" when a fallback exists; do the fallback and queue the PC step in queue/pc.md (L-016)
- The permission classifier blocks sub-agents that read the owner's other vaults unless the owner asked; keep workers inside this repo (L-018)
- routing by judgment sent tasks to the wrong note; route by router.json words and replay the real ask through hooks/prompt-router.mjs after adding a word (L-019)
- a session built a separate page because the router never named the existing tool; name every tool/skill in index.md and reuse it before building new (L-020)
- faces with inverted (negative) scale were invisible; check winding/normals face outward before writing geometry (L-023)
- owner rejected a 4-part draft and a bare slab when a meadow was asked; no placeholders, the named theme is built first everywhere the camera sees (L-025)
- followed an old stored copy of the rules; the owner's latest word beats any stored rule, update that rule in the same task (L-026)
- UI rejected 8 times for ad hoc colours, generic fonts, black outlines, overlaps; decide references + palette + layout + type first, check palette and overlaps by script on a render (L-028)
- Hook commands must be `node "./hooks/x.mjs"` with ROOT from the hook file's location: after a session moves folders CLAUDE_PROJECT_DIR still points at the OLD folder, so $CLAUDE_PROJECT_DIR paths silently miss (hooks run in Git Bash, cwd = vault) (L-029)
- Never make a hook fail closed (`|| echo deny`): one broken guard locked every edit and shell call, including the fix (L-030)
- Node tool paths use fileURLToPath(import.meta.url), never URL.pathname (breaks on Windows and spaces) (L-034)
- skill-miss only counts writes outside vault plumbing (hooks, scripts, notes, router) (L-048)
- owner rules are saved and enforced the same turn; a met goal still gets one concrete improvement (L-051)
- upload hub assets from .worktrees/, not the scratchpad (L-052)
- never pass the LITTLE~1 short path to Artifact tools; long path for out_dir, .worktrees/ for uploads (L-053)
- scripted JS patches: no trailing // comments inside replaced fragments; node --check immediately after (L-062)
- before a hub build, ask the owner once to allow ArtifactData; never self-edit permissions (L-068)
- never store standing auto-approval rules; push only when the owner says push in that turn, else commit and say not pushed (L-071)
- db reads with out_dir go to .worktrees/; project doc = collection 'projects' + doc_id; geo = 'projects/<id>/geo' (L-073)
- crew: <=5 min pieces with exact defect lists and a hard tool-call cap; brain works in parallel, never idle (L-075)
- crew: <=5 min pieces, exact defect lists, hard caps; brain works in parallel; TaskStop each worker on report (L-077)
- in a worktree session edit tools under the worktree path, run them from there, then port the diff to main for the commit (L-078)
- complaints are never simple tier; Improved counter accepts one-line or numbered/bulleted lists (L-102)
- crew routes only on /crew or an explicit ask to use sub agents/workers (L-103)
